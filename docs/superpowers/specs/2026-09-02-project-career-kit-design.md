# 后端项目求职素材 Skill 设计规格

> **历史规格，已废弃：** 本文包含已替换的证据审计输出要求，不能作为当前实现或验收依据。请以 [`2026-09-07-project-career-kit-v2-design.md`](2026-09-07-project-career-kit-v2-design.md) 和 [`project-career-kit/references/output-contract.md`](../../../project-career-kit/references/output-contract.md) 为准。

## 目标

创建一个名为 `project-career-kit` 的单一 Agent Skill，供支持 `SKILL.md` 的 Codex、Claude Code/Claude Cloud 等客户端使用。用户将一个后端项目交给客户端扫描后，得到可直接编辑的中文 Markdown 简历素材、面试逐字稿、项目流程图和证据审计表。Skill 只读分析源码，不修改业务代码。

## 交付物

默认在目标项目下创建 `career-kit/`：

- `resume.md`：项目背景、业务目标、后端技术栈、个人职责，以及一句话版、三条版和详细版表述。
- `interview-script.md`：60 秒版、3 分钟版、核心请求链路逐字稿、难点与亮点、取舍、故障处理和高频追问。
- `flowchart.md`：Mermaid 业务流程图；复杂链路按条件增加时序图或架构图。
- `evidence.md`：每个结论对应的文件路径、行号或片段、证据等级（已证实/合理推断/未知）和待确认项。

回复中同时给出结果摘要和需要用户确认的事实。

## 分析流程

1. 读取用户参数：项目路径、目标后端岗位、中文输出（固定默认）、篇幅和本人实际参与范围。缺少路径时只询问路径；其他缺失项使用默认值并标注待确认。
2. 运行无第三方依赖的项目清单脚本（不可用时采用 `rg --files` 或等价命令），识别语言/运行时、框架、入口、路由、服务、数据访问、缓存、消息、外部依赖、测试、CI/CD 和部署配置。README 缺失时不停止：按“依赖/构建清单 → 启动入口 → 路由或 Handler → 领域服务 → 数据模型与迁移 → 测试 → 部署配置 → Git 提交信息”的顺序建立项目理解；如果这些证据仍不足，明确写出业务背景未知。
3. 按证据优先级读取高价值文件和关键代码片段，而不是逐行遍历所有文件。跳过 `.env`、密钥、证书、私钥、供应商目录、构建产物、二进制和超大文件；任何输出都不得包含秘密值。目录名、包名、类名和单条提交信息只能作为线索，不能单独证明业务用途。
4. 建立证据表，再生成四个 Markdown 文件。个人职责必须来自用户确认、Git 作者信息或明确代码证据；仅凭目录结构推断的职责必须标为推断。
5. 对结论做一致性检查：技术栈有证据、指标可追溯、未知项显式标记、Mermaid 代码可复制且无明显语法错误。

## 后端内容重点

分析应优先解释请求从网关/鉴权到 Handler、Service、Repository/ORM、数据库/缓存/队列和外部服务的路径，并覆盖事务与一致性、幂等、并发、性能、可靠性、异常、日志监控和测试。只有项目中存在相应证据时才写这些主题。

## 设计边界

- 技能描述保持厂商无关，不依赖 MCP、网络或特定操作系统；脚本失败不阻断 Markdown 产出。
- 默认中文和 `.md`，Mermaid 作为 Markdown 代码块保存，不强制生成图片或安装渲染器。
- 不虚构业务规模、性能数字、个人职责、线上结果或未被代码支持的技术；可用 `【待补充：指标】` 作为占位。
- 不向外部服务上传源码，不在源项目中写入除 `career-kit/` 以外的文件。

## 验证策略

先使用没有该 Skill 的独立代理运行至少三个压力场景：README 与代码矛盾、完全没有 README 但有源码和配置、项目缺少个人贡献信息、仓库含敏感文件/大文件。记录模型是否编造事实、遗漏链路或泄露内容。完成 Skill 后用同一场景复测，再做一次新项目的独立前向测试；最后运行 Skill 结构校验脚本并检查脚本的退出码和输出。
